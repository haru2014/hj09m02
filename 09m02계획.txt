첨부 과제를 기준으로 보면, 제안하신 아이디어는 **단순 논문 검색기가 아니라 “반려동물 연구동향 AI 비서”**로 설계하는 것이 가장 적합합니다. 과제의 핵심 요구가 **시계열 데이터 분석 → DB 저장 → 데이터 요약 → GPT 컨텍스트 주입 → 자연어 질의응답**이기 때문입니다. 

## 1. 프로젝트 주제 제안

### 프로젝트명

**Pet Research Navigator**
부제: **반려동물 연구논문·연구동향 AI 비서**

핵심 기능은 다음처럼 정의하면 됩니다.

> 사용자가 `관절`, `행동`, `피부`, `질병` 등의 연구주제를 입력하면 해당 분야의 반려동물 논문을 찾아 연도별로 정리하고, 주요 연구내용·연구방법·핵심 키워드와 시간에 따른 연구동향 변화를 설명해주는 AI 서비스

예를 들어 사용자가 단순히

> **관절**

이라고 입력하면 AI가 다음과 같이 응답하는 구조입니다.

**관절 연구 개요 → 연도별 논문 수 → 대표 논문 → 논문별 요약 → 주요 연구방법 → 핵심 키워드 변화 → 연구동향 변화 → 최근 연구 방향**

---

# 2. 이 프로젝트가 첨부 미션과 잘 맞는 이유

첨부 과제에서는 최소 **100개 이상의 데이터 포인트**를 이용하고, 데이터에서 기간·개수·통계·최근 추세를 생성하도록 요구하고 있습니다. 

따라서 논문 데이터를 다음처럼 바꾸면 됩니다.

### 일반적인 논문 DB

`논문 제목 → 저자 → 초록`

에서 끝나는 것이 아니라,

### 이번 프로젝트

`연도 → 연구주제 → 논문 수 → 주요 키워드 → 연구방법 → 연구대상 → 연구결과`

형태의 **시계열 연구 데이터**로 바꾸는 것입니다.

이렇게 하면 예를 들어:

| 연도   | 분야 | 논문수 | 주요 연구주제              | 주요 방법       |
| ---- | -- | --: | -------------------- | ----------- |
| 2015 | 관절 |  12 | OA, hip dysplasia    | X-ray       |
| 2018 | 관절 |  18 | OA, gait             | Force plate |
| 2021 | 관절 |  31 | gait, rehabilitation | IMU         |
| 2024 | 관절 |  47 | AI gait analysis     | AI·wearable |
| 2025 | 관절 |  55 | remote monitoring    | AI·sensor   |

와 같은 데이터가 만들어집니다.

AI는 이를 보고

> 과거에는 영상진단과 임상검사가 중심이었으나 최근에는 보행센서·웨어러블·AI 기반 지속 모니터링 연구가 증가하고 있다.

처럼 **연구 흐름을 설명**하게 됩니다.

# 5. 데이터 수집 범위

미션용 MVP에서는 범위를 제한하는 것이 좋습니다.

제가 권하는 것은:

**대상 동물**

* 개
* 고양이

**기간**

* 2010~2025년
* 2026년은 `현재까지(YTD)` 별도 표시

**분야**

* 7개

**논문**

* 분야별 최소 20~30편
* 전체 약 **150~300편**

정도입니다.

이 정도만 있어도 과제에서 요구하는 최소 100개 데이터 포인트를 충분히 충족할 수 있습니다. 

논문 출처는 MVP에서는 **PubMed를 중심**으로 하고 이후 Crossref, OpenAlex, Google Scholar 검색결과 등을 확장하는 구조가 좋습니다.

# 8. AI 답변 구조

AI가 매번 자유롭게 답변하게 하지 말고 **답변 템플릿을 고정**하는 것이 좋습니다.

예:

> **반려견 관절 연구동향**
>
> **1. 연구현황**
> 2010~2025년 관절 관련 논문 ○○편이 확인되었습니다.
>
> **2. 주요 연구주제**
> Osteoarthritis, gait analysis, rehabilitation 연구가 가장 많이 나타났습니다.
>
> **3. 연구 변화**
> 초기에는 영상진단과 수술 결과 연구가 중심이었으나 이후 force plate와 gait analysis 연구가 증가했습니다.
>
> 최근에는 IMU, wearable sensor, AI 기반 보행분석 연구가 확대되는 경향을 보입니다.
>
> **4. 주요 논문**
>
> * 논문 A
> * 논문 B
> * 논문 C
>
> **5. 최근 연구 방향**
> 병원 단회검사에서 일상생활 기반 지속 모니터링으로 연구범위가 확대되고 있습니다.

# 9. Firestore 구조

첨부 과제에서 Firestore를 사용하고 `data`, `conversations` 컬렉션을 구성하도록 요구하고 있습니다. 

여기에 논문용 컬렉션 하나를 추가하면 됩니다.

```text
Firestore

papers
 ├ paper001
 ├ paper002
 └ paper003

data
 ├ 2010_joint
 ├ 2011_joint
 ├ 2012_joint
 └ ...

conversations
 ├ conversation001
 └ conversation002
```

### papers

```json
{
 "title": "...",
 "year": 2024,
 "species": "dog",
 "topic": "joint",
 "subtopic": "osteoarthritis",
 "method": "IMU",
 "summary": "...",
 "keywords": ["gait","OA","sensor"]
}
```

### data

```json
{
 "date": "2024-01-01",
 "value": 37,
 "topic": "joint",
 "memo": "AI, gait, IMU, wearable 연구 증가"
}
```

이렇게 하면 첨부 과제가 요구하는 기본적인

`date + value + memo`

구조도 유지할 수 있습니다.

# 12. 논문 요약에서 반드시 지켜야 할 원칙

이 프로젝트에서는 이것이 매우 중요합니다.

AI가 논문을 임의로 해석해서는 안 됩니다.

논문마다:

```text
연구목적
연구대상
표본수
연구방법
주요 결과
결론
```

을 구조화합니다.

그리고 가능하면

> **초록 기반 요약**

이라고 표시하는 것을 추천합니다.

특히 GPT에게

```text
제공된 논문 정보 이외의 연구결과를 생성하지 않는다.
표본수나 효과크기를 추측하지 않는다.
논문에 없는 결론을 만들지 않는다.
```

라는 지침을 넣는 것이 좋습니다.

# 14. 이 프로젝트에서 하지 않는 것이 좋은 것

처음부터 다음을 넣으면 난도가 크게 올라갑니다.

* 모든 동물 종 논문 검색
* 모든 질병 검색
* 논문 PDF 전체 자동 분석
* 실시간 Google Scholar 크롤링
* 자체 벡터DB
* 복잡한 RAG
* 논문 추천 알고리즘
* citation network 분석

이번 미션에서는 **RAG 논문검색 서비스**까지 갈 필요가 없습니다.

우선

> **구조화된 논문 DB + 연도별 통계 + GPT 컨텍스트 주입**

만으로 만드는 것이 좋습니다.

과제 자체에서도 핵심 학습목표를 **데이터 요약 정보를 시스템 프롬프트에 넣는 컨텍스트 주입**으로 명확히 제시하고 있습니다.

# 15. 최종적으로 만들 서비스의 모습

저라면 이번 미션을 다음 한 문장으로 정의하겠습니다.

> **반려동물 관련 연구논문을 주제와 연도별로 구조화하여, 사용자가 ‘관절’, ‘행동’, ‘피부’ 등의 키워드를 입력하면 주요 논문과 연구내용을 요약하고 시간에 따른 연구주제·방법·기술의 변화를 설명해주는 AI 연구동향 비서**

특히 **박사·연구자 관점에서 좋은 프로젝트인 이유는 “논문 요약 AI”가 아니라 “연구동향을 데이터로 보는 AI”라는 점**입니다.

즉,

**논문검색 → 논문요약 → 연도별 데이터화 → 연구방법 변화 → 핵심 키워드 변화 → 연구동향 해석**

이라는 흐름으로 잡는 것을 추천합니다.

### 권장 MVP 구조

**2010~2025년 × 7개 연구분야 × 150~300편의 논문**으로 시작해,

`관절`처럼 단어 하나만 입력해도 **① 연구현황 → ② 연도별 변화 → ③ 대표 논문 → ④ 논문 요약 → ⑤ 연구방법 변화 → ⑥ 최근 연구동향**까지 보여주는 수준을 최종 목표로 잡으면, 첨부 미션의 요구사항과 사용자께서 원하는 반려동물 연구 전문성을 둘 다 잘 살릴 수 있습니다.
