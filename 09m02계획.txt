### 1. 프로젝트 개요 및 데이터 연계 전략

* **서비스 명칭**: 반려동물 행동 모니터링 AI 비서 (`Pet-Action AI Assistant`)
* **이전 미션 데이터 연계 방식**:
* 미션 01에서 전처리·집계한 `pet_action_timeseries.csv` 데이터셋(일자별 `footup` 등 특정 행동 발생 횟수/프레임 수치 100개 이상)을 활용합니다.


* 데이터 스키마: `(date: YYYY-MM-DD, value: float/int, memo: string)`

* 예시: `{"date": "2020-11-05", "value": 42, "memo": "dog-footup 행동 42건 감지"}`





* **핵심 아키텍처**:
* **Backend**: FastAPI (Python 3.10+), Firebase Admin SDK (Firestore), OpenAI API


* **Database**: Firebase Firestore (`data`, `conversations` 컬렉션)


* **Frontend**: Vanilla HTML/CSS/JavaScript (프레임워크 없음)


* **Deploy**: Backend는 Render, Frontend는 Vercel

* `data` 컬렉션: `{ id: string, date: "YYYY-MM-DD", value: number, memo: string, created_at: timestamp }`

* `conversations` 컬렉션: `{ id: string, title: string, created_at: timestamp, messages: [{ role: "user"|"assistant", content: string, timestamp: string }] }`

#### [2단계] 백엔드(FastAPI) 개발

프로젝트 구조는 유지보수성과 평가 기준(라우터/서비스 분리)을 만족하도록 모듈화합니다.

```text
backend/
├── app/
│   ├── main.py              # FastAPI 앱 생성, CORS 설정, 라우터 등록
│   ├── core/
│   │   ├── config.py        # 환경변수 로드
│   │   └── firebase.py      # Firestore 클라이언트 초기화
│   ├── models/
│   │   ├── data.py          # Pydantic 스키마 (DataCreate, DataUpdate, DataResponse, SummaryResponse)
│   │   └── conversation.py  # Pydantic 스키마 (ChatRequest, ConversationResponse 등)
│   ├── routers/
│   │   ├── data.py          # /api/data 엔드포인트
│   │   ├── conversations.py # /api/conversations 엔드포인트
│   │   └── chat.py          # /api/chat 엔드포인트
│   └── services/
│       ├── data_service.py  # Firestore data CRUD 및 요약/통계 계산 로직
│       └── ai_service.py    # OpenAI API 호출 및 컨텍스트 주입 로직
├── requirements.txt
├── Dockerfile (Render 배포용 또는 render.yaml)
└── init_data.py             # 미션 01의 CSV를 Firestore data 컬렉션에 일괄 업로드하는 스크립트
```[cite: 1, 3]

**세부 API 구현 사양:**
1. **데이터 CRUD 및 요약 API (`/api/data`)**:
   * `POST /api/data`: 단일 데이터 검증 후 등록[cite: 3]
   * `GET /api/data`: 전체 데이터 정렬(date 기준) 조회[cite: 3]
   * `PUT /api/data/{id}`: 데이터 수정[cite: 3]
   * `DELETE /api/data/{id}`: 데이터 삭제[cite: 3]
   * `GET /api/data/summary`:
     * 집계 항목: 전체 기간(`period`), 총 건수(`count`), 평균/최대/최소/합계(`metrics`), 이동평균/변화율 기반 최근 추세(`trend` - 예: "최근 7일간 완만한 증가세")[cite: 1, 3].
2. **대화 관리 API (`/api/conversations`)**:
   * `GET /api/conversations`: 대화 목록(id, title, created_at) 조회[cite: 3]
   * `GET /api/conversations/{id}`: 특정 대화의 전체 메시지 목록 조회 (불러오기 UX용)[cite: 3]
   * `POST /api/conversations`: 신규 대화 세션 생성 또는 수동 저장[cite: 3]
   * `DELETE /api/conversations/{id}`: 대화 삭제[cite: 3]
3. **AI 챗봇 API (`/api/chat`)**:
   * `POST /api/chat`:
     * 요청: `{ "message": "최근 반려견 활동량이 늘었어?", "conversation_id": "선택사항" }`
     * 처리 흐름:
       1. `data_service.get_summary()` 호출하여 최신 요약 데이터 생성[cite: 3].
       2. 시스템 프롬프트 구성:
          ```text
          당신은 반려동물 행동 및 건강 분석 전문 AI 비서입니다.
          [현재 반려동물 행동 수집 데이터 요약]
          - 기간: {period}
          - 총 레코드 수: {count}일치
          - 주요 통계: {metrics}
          - 최근 트렌드: {trend}
          위 데이터를 엄격한 근거로 삼아 사용자의 질문에 사실 기반으로 답변하세요.
          ```[cite: 3]
       3. OpenAI ChatCompletion 호출 (`gpt-4o-mini` 또는 지정 모델 사용, max_tokens 제한)[cite: 3].
       4. 결과를 `conversations` 컬렉션에 자동 누적/저장[cite: 3].
       5. AI 응답 메시지 및 conversation_id 반환[cite: 3].

#### [3단계] 프론트엔드(Vanilla HTML/CSS/JS) 개발

*제약 조건: 외부 프레임워크(React, Vue 등)를 사용하지 않고 순수 HTML/CSS/JS로 구현합니다[cite: 3].*

1. **화면 레이아웃 (반응형 2-패널 또는 3-패널 구조)**:
   * **좌측 패널**: 대화 기록 목록(히스토리), 대화 불러오기 버튼, 새 대화 시작 버튼[cite: 3].
   * **중앙 패널 (메인)**:
     * 상단: **데이터 요약 대시보드 카드** (기간, 건수, 평균값, 최근 트렌드)[cite: 3].
     * 중단: **채팅 창** (사용자/AI 말풍선, AI 생성 중 로딩 스피너)[cite: 3].
     * 하단: **메시지 입력창 및 전송 버튼**[cite: 3].
   * **우측/하단 패널**: **데이터 관리(CRUD)** 테이블 및 입력 폼 (새 레코드 등록 모달 또는 인라인 폼, 삭제 버튼)[cite: 3].
2. **비동기 통신 (`script.js`)**:
   * `config.js`를 분리하여 `API_BASE_URL`을 설정(로컬 vs 배포 환경)[cite: 3].
   * `fetch` API를 사용하여 데이터 추가/삭제 시 상단 요약 카드와 데이터 목록이 즉시 갱신되도록 이벤트 처리.
   * 채팅 전송 시 `loading indicator` 노출 후 답변 도착 시 렌더링[cite: 3].
   * 대화 목록 클릭 시 `GET /api/conversations/{id}`를 호출하여 이전 메시지 창에 복원[cite: 3].

#### [5단계] 클라우드 배포 및 검증

1. **백엔드 배포 (Render)**:
   * GitHub 레포지토리 푸시 후 Render에서 `Web Service` 생성[cite: 3].
   * Build Command: `pip install -r requirements.txt`
   * Start Command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
   * Environment Variables 설정:
     * `OPENAI_API_KEY`[cite: 3]
     * `FIREBASE_SERVICE_ACCOUNT_JSON` (JSON 파일 전체 내용을 문자열로 등록 후 앱 시작 시 파싱하도록 처리)[cite: 3]
     * `ALLOWED_ORIGINS` (Vercel 도메인)[cite: 3]
   * 배포 후 `https://<render-url>/docs` 접속 및 Swagger 정상 동작 확인[cite: 3].
   * 무료 티어 콜드 스타트(Sleep) 대응 안내 문구를 프론트엔드 로딩창에 명시 ("서버 기상 중 최대 1분 소요될 수 있습니다")[cite: 3].
2. **프론트엔드 배포 (Vercel)**:
   * 프론트엔드 소스 루트 지정 후 Vercel에 정적 사이트로 배포[cite: 3].
   * 프론트엔드 배포 완료 후 백엔드의 `ALLOWED_ORIGINS`에 Vercel 도메인 추가하여 CORS 에러 방지[cite: 3].

### 3. 체크리스트 및 주의사항
* **보안**: `serviceAccountKey.json`과 `.env`는 절대 GitHub 저장소에 커밋하지 않도록 `.gitignore`를 철저히 점검합니다[cite: 3].
* **비용 방지**: OpenAI 호출 시 `max_tokens: 300~500` 정도로 설정하여 불필요한 토큰 낭비를 방지합니다[cite: 3].
* **CORS**: 로컬 테스트 주소(`http://localhost:5500`, `[http://127.0.0.1:5500](http://127.0.0.1:5500)`)와 실제 배포된 Vercel 도메인이 FastAPI의 `CORSMiddleware`에 모두 등록되어 있어야 통신 오류가 발생하지 않습니다[cite: 3].

```
